# About

`hbctl` is a fast, single-binary Rust CLI client built for interacting with remote [Homebox][1] v0.26+ instances over the `/api/v1` REST API. It is designed for both interactive terminal workflows and scriptable AI-agent automation, providing deterministic JSON output, safe read-modify-write updates, bulk operations, deduplication, attachment management, maintenance logs, inventory statistics, templates, barcode lookup, label/QR generation, notifiers, filtered exports, and portable full-inventory backups.

## :sparkles: Features

- **Agent-Friendly Output:** Emit compact JSON (`--json` / `--output json`), table, plain, CSV, or Markdown (`--output`), project top-level or custom fields (`--select`), print only affected IDs (`-q` / `--quiet`), or preview mutating HTTP calls without touching the server (`--dry-run`). Data writes cleanly to `stdout` while diagnostics stay on `stderr`.
- **Full Item Lifecycle & Bulk Ops:** Create, read, update, upsert, delete, duplicate, move, and render parent/location hierarchies (`item tree`, `item path`), with automatic `--asset-id` resolution (including dashed numeric asset IDs like `000-001`), warranty/insurance/sold/archived fields, and bulk `update`, `move`, and `delete` selectors (`ID...`, `--items-from`, tag/parent/type filters). Custom fields supplied during `item create` are automatically persisted via a follow-up `PUT`.
- **Two-Pass Deduplication:** Detect exact and near-duplicate inventory items (`hbctl item dedup`) using Pass 1 exact case-insensitive name matching and Pass 2 Jaccard token similarity (stripping version numbers and common stop-words). Deterministic keeper selection retains the most descriptive entry and optionally sums quantities (`--merge`).
- **Bulk Import & Idempotent Upsert:** Import JSON or CSV records (`hbctl item import`) or upsert single items (`hbctl item upsert`) with configurable match keys (`name`, `model`, `serial`, `field:KEY`), match modes (`exact`, `contains`, `fuzzy`), conflict actions (`update`, `skip`, `attach-only`), and `--fill-missing` preservation.
- **Attachments, Links & Image Optimization:** Upload local files, stdin streams, or remote HTTP(S) URLs (`--attach`, `--attach-url`) with duplicate skipping by default, mark primary photos (`--primary`, `attachment set-primary`), update attachment metadata (`attachment update`), attach external links (`attachment add-link`), stream-download attachments individually or in bulk, and automatically resize/compress oversized images in memory (`--optimize` / `auto_optimize`).
- **Structured Search & Typed Custom Fields:** Query items by free-text, tag, entity type, parent, archived state, warranty expiration window (`--warranty-expiring`), model, serial, manufacturer, or custom field (`KEY` / `KEY=VAL`) with AND or OR (`--any`) semantics and `--with-path` breadcrumbs, and manage typed custom fields (`text`, `number`, `boolean`) via `hbctl field`.
- **Maintenance, Statistics, Templates & Barcodes:** Manage maintenance entries (`hbctl maintenance`), inspect group/tag/location/entity-type/purchase-price breakdowns (`hbctl stats`), create and apply item templates (`hbctl template`), and look up barcode product metadata (`hbctl barcode` / `item create --from-barcode`).
- **Labels, QR Codes, Notifiers & Raw API:** Generate or server-print labels (`hbctl label`), render QR code images (`hbctl qr`), run server actions (`hbctl actions`), manage Shoutrrr notification channels (`hbctl notifier`), and issue raw authenticated API requests (`hbctl api`).
- **Portable Backups & Filtered Exports:** Create directory or `.tar.gz` full-inventory backups (`hbctl backup` with `manifest.json`, hydrated JSON datasets, and disambiguated attachments) and export filtered items to JSON, CSV, or Markdown with custom sorting, column aliases, alignment, and placeholders (`hbctl export`).
- **Multi-Instance Profiles:** Configure named `[profiles.<name>]` entries in `~/.config/hbctl/config.toml`, inspect effective settings (`hbctl config show`), list/switch profiles (`hbctl config profiles`, `hbctl config use`), or target via `--profile` / `-P` / `HBCTL_PROFILE` with profile-isolated credential storage.
- **Portable Single Binary:** Prebuilt binaries for Linux (AMD64, ARM64, ARMv7, ARMv6), macOS, and Windows, complete with shell completions, a UNIX man page, and an integrated GitHub release self-updater (`hbctl update`).

## :shield: Security & Reliability Architecture

- **OS Keyring with `0600` Fallback:** Credentials saved via `hbctl auth login` are stored in the system keyring (`Secret Service`/D-Bus on Linux, Keychain on macOS, Credential Manager on Windows) and automatically fall back to a `0600` local file (`~/.config/hbctl/credentials.json` inside a `0700` directory) in headless environments. See [Credential Storage & Headless Fallback](./security.md#credential-storage-headless-fallback).
- **Mandatory Secret Redaction:** `Authorization` headers are always masked as `Bearer ***` in `hbctl auth status`, `hbctl config show`, `--dry-run` request previews, and error diagnostics, with raw secret strings scrubbed from error text. `hbctl notifier list` and `notifier test` redact embedded Shoutrrr credentials unless `--reveal` is passed, and `hbctl backup` strips userinfo from `sourceUrl` in `manifest.json`. See [Secret Redaction & Dry-Run Safety](./security.md#secret-redaction-dry-run-safety).
- **Safe `GET -> Merge -> PUT` Mutations:** Item, template, and custom field updates fetch the current server state, merge changes locally, and submit a complete `PUT` payload so unrelated fields and attachments are never clobbered.
- **Go-`null` Tolerant Deserialization:** REST models handle Homebox v0.26+ nullable arrays (`null` instead of `[]`) and snake/camel-case JSON aliases cleanly without deserialization failures.
